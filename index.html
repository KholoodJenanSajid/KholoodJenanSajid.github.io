Story

I fell into data the way most engineers do — by accident, then obsession. I started with backend code and DSA (250+ LeetCode problems, a scrappy 3rd place in a coding challenge), and somewhere along the way I realised the most interesting bug in any system is usually a data bug.

These days I spend my time on the unglamorous middle of the stack — ETL, staging layers, data lakes, orchestration, and the hundred small checks that stand between raw upstream files and a dashboard someone actually trusts.

I like pipelines that fail loudly, code that reads like prose, and systems where the next engineer — including future me — doesn't need a map to change something.
